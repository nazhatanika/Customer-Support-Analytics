Ticketing Management System — Architecture

Postgres · Redis · FastAPI · React · Power BI · ML — an event-sourced support desk (fake data, real engineering)

Full-stack core

  • • PostgreSQL 16 — event-sourced source of truth
  • • Redis 7 — cache, rate limits, refresh tokens
  • • FastAPI + SQLAlchemy 2 + Alembic
  • • React 18 (Vite, JS) + MUI + TanStack Query
  • • pytest suite + GitHub Actions CI

Analytics & BI

  • • Metrics defined once, in SQL views
  • • Power BI: Ops · Transfers · Escalations · Costs
  • • Data-quality validation page (~10 checks)
  • • insights.md — findings with cited queries
  • • Mac note: Desktop is Windows-only → Service + API push path

Machine learning

  • • Target: recontact within 7 days of resolution
  • • ~25 features, leakage-guarded, time-based split
  • • LogisticRegression baseline → LightGBM
  • • PR-AUC + cost-based decision threshold
  • • SHAP drivers → risk flags written back to Postgres
